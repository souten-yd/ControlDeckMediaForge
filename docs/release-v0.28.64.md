# v0.28.64 — Blender状態取得の応答停止対策

設定画面の初期化・状態更新で行うBlender登録、ファイル検査、DB照会を
イベントループとは別のスレッドへ移します。検査が遅い場合にも他のHTTP処理を進められます。
連続して要求を取り消しても、開始済みの登録処理は終端まで追跡します。

状態の公開フィールド、導入・削除の判定、既存画像・G8・制作版の契約は変更しません。
DB移行、Blenderの更新、モデルの追加取得は不要です。

## 検証と残件

PR #446でHTTP・WebSocket・初期化・3回連続取消の回帰検査を追加しました。
専用ソースサーバーでは、登録検査を明示的に保留中も別HTTP接続のhealthが約1.52msで応答し、
解除後に状態取得が完了しました。人工的な検査待機であり、長時間セットアップの認証試験ではありません。

署名配布・公開物の再取得・導入済み環境での受入は準備中です。
全セットアップI/Oの分離、Host credential維持、統合3D Studio全体の完了は別の残件です。
