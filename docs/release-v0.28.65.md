# v0.28.65 — Blenderセットアップ受付の応答停止対策

導入・Web操作環境の導入・更新・修復・切替・取消の受付で行う同期DB/ファイル処理を、
イベントループとは別のスレッドへ移します。実行タスクの開始はイベントループ側で行います。
同時要求の二重作成を防ぎ、連続取消でも受付済み操作を見失わないようにします。

公開入力・出力、導入元、削除保護、既存画像・G8・制作履歴の契約は変更しません。
DB移行、Blender更新、モデルの追加取得は不要です。

## 検証と残件

PR #449ではHTTP/WSの6経路、3回連続取消と停止、同時要求の重複防止を検査しました。
専用環境の実HTTPでは受付待機中もhealthが約1.52msで応答し、その後、実固定アーカイブから
Blender 4.5.9を導入してGLB入出力検査まで成功しています。待機は明示的な試験用条件です。

署名配布・公開物の再取得・導入済み環境での受入は準備中です。
実行中の全同期I/O、セットアップのHost credential維持、統合3D Studio全体は未完了です。
