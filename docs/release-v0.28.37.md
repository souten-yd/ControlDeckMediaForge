# v0.28.37 — 制作の再試行でBlender環境を保持

失敗・取消後の制作Jobを再試行するとき、元のJobに記録されたBlender環境を使います。
途中で既定のBlenderを切り替えても、再試行を別の版へ自動的に移しません。
元の環境が利用できない場合は明示エラーとなり、同じ版の再導入が必要です。
既存sceneの編集・材質処理では、元の版が現在版であることの検査も維持します。

sourceの実Blenderで、4.5.9の待機Job取消→既定4.5.13へ変更→元4.5.9で再試行成功を確認。
別の隔離試験では、材質処理失敗→同じ入力で再試行し、成功済み画像・形状・旧版を保持し、
材質の新しい版と2素材だけが増えることを確認しました。Host制御は診断fixtureであり、
導入済みHostやブラウザでの再試行受入とは区別します。

公開schema・Asset/scene/Job保存形式・runtime registryは変更しません。
Blender本体、モデル重み、利用者のグローバル設定も変更しません。
統合3D Studioの全必須受入は引き続きPARTIALです。

## 更新・ロールバック

ControlDeckの標準署名検証付き更新を使用します。更新前にJob/GUI/環境処理の終端を確認し、
DBとruntime registryのsnapshotを保持してください。0.28.36からデータ変換はなく、
0.28.36へのcore rollbackは保存形式互換です。ただし旧版では今回の再試行修正を失います。
0.28.34以前へのrollbackは0.28.35 release noteのregistry互換条件も確認してください。
