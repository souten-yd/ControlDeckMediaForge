# v0.28.53 — 修復時の稼働Blender保護

Blenderの修復候補を公開する直前に、実行中のJob・GUI・作業コピーの参照を再検査します。
使用中なら元の環境を保持して修復を拒否し、停止後に再試行できます。
参照の取得と差し替えを排他にし、差し替え開始後のサービス停止も処理の完了を待ちます。
停止済みなら、既定版や履歴から参照される版も引き続き修復できます。

## 検証と配布状態

PR #390で実装。候補検証中に参照が増える2件の回帰テストで修正前の問題を再現しました。
隔離した実Blender4.5.9とHTTPで、稼働中の修復拒否→停止→同版修復成功を46.009秒で確認。
固定アーカイブの実展開・probeを実行し、既存実行ファイル・registry・制作物をhashで照合しました。
実装時の全1,348テストが成功しています。
署名公開・公開4ファイルの再取得照合・実Host署名検証を確認しました。
標準更新10.240秒でhealthyとなり、DB全テーブルとBlender登録を保持しています。
導入済みHostのopaque iframeでも、実Blender GUI接続中の同版修復拒否と、
GUIの稼働維持・旧シーン/実行ファイル/registryの保持・終了時の回収を確認しました。
停止後の正常修復は隔離sourceで確認済みですが、導入済みHostではまだ未確認です。
最新の結果は[実装状況](implementation-status.md)に記録します。

## 互換性と残る範囲

公開API/schema/tool名、DB、Blender版・archive identityの変更はありません。
既存画像・G8加工・ビューワーを維持します。更新は稼働JobとGUIがない時に実施してください。
稼働中の別版導入・probe失敗などの全故障条件を完了した版ではありません。
統合3D Studio全体や、ゲーム用の有機変形・IK・歩行・engine対応は引き続き開発中です。
