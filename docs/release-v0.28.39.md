# v0.28.39 — 透過素材の生成と、まとめて頼む入口

重ねて使う素材（sprite / icon / emblem / ui_element）が必ず失敗していた問題を修正します。
これらの用途は透過を要求しますが、画像モデルは透過を出力しません。生成物は不透明のまま
届き、検査が `alpha_missing` で落とす経路しか存在しませんでした。実機ログでは
`alpha_intent: required` の依頼が例外なく502で返っており、本日の74件中20件がこれです。

単色背景で描かせ、生成後にその背景を決定的に抜きます。抜き方は縁を測った実測色を鍵にし、
縁から届く範囲だけを対象にします。背景が被写体へ falloff している部分は色差に応じた
半透明にし、混ざった画素からは背景の寄与を差し引きます。抜けない画は書き換えず、
従来どおり理由を名指しで失敗します。透過するかどうかは用途で決まり、`texture` や
`background`、明示された `alpha_intent: forbidden` には掛かりません。

`media.generate.batch` を追加します。N件（最大50）の別々の素材を1コールで順に作ります。
1件ずつ呼ぶと、その都度Hostが言語モデルを降ろして載せ直し、会話の文脈を読み直します。
実測では画像1枚13〜16秒に対し、読み直しが40〜350秒でした。batchの間は画像モデルを
載せたままにし、2件目以降は載せ直しを払いません。全体を縛る時計は置かず、1件ごとの
worker timeoutと、前へしか進まない進捗報告で終わりを決めます。

`asset_brief` の説明文に、透過を求めるときは背景に触れないことを明記しました。呼び出し側が
背景を注文したままだと単色背景の指示と衝突するため、生成へ渡す文言からは背景の節を
決定的に取り除きます。利用者が書いた文言そのもの（評価器の判定基準・資産名の素）は
変更しません。

同時に、profileを付けたjobでLoRAの起動語が消えていた既存不具合を直しました。worker へ
渡す文言の組み立てが三つの独立した代入になっており、後のものが前のものを作り直していました。

## 検証

決定的な後処理は、OpenCodeが本アドオンで作ったgameの実生成物（1024x1024、22件）で
確認しました。単体テストは1161件が成功しています。実機GPUでのbatch実行と、導入済みHostでの
受入は未実施です。ControlDeck側のagent tool待機（進捗基準への変更）とMCP bridgeの
待ち時間は本リリースの範囲外で、別途ControlDeck側の更新が要ります。

## 更新・ロールバック

ControlDeckの標準署名検証付き更新を使用します。0.28.38からデータ変換はありません。
0.28.38へのcore rollbackは保存形式互換ですが、透過素材の生成は再び `alpha_missing` で
失敗し、`media.generate.batch` は消えます。公開契約は追加のみで、既存の
`media.generate` の要求・応答は変更していません。
