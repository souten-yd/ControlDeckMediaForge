# v0.28.70 — 画像ジョブの認証更新と終了通知の回収

通常の画像生成ジョブが資源を待っている間も、有効期限前にHost認証を更新します。
割当て前はJob認証、割当て後は既存のlease認証を更新し、期限切れからの自己再発行は行いません。
元の利用者・権限・親ジョブとの関係を維持します。

終了通知が届かなかった場合は、ローカルの結果を保持します。同じ利用者が再認証すると、
MediaForge自身が終了を管理するジョブだけをHostと照合します。Hostの結果が異なる場合は
上書きせず不一致として保存します。接続先の親ワークフローを勝手に終了させません。
停止時の遅れた進捗更新で、確定済みジョブが実行中へ戻る競合も防ぎます。
配布データから開発時のPythonキャッシュを除外し、workerのソースと必要な素材だけを同梱します。

## 更新・旧版への復帰

既存DBにprivateな `owned_job_terminals` テーブルと索引を追加します。
新しく受け付ける対象ジョブのHost ID・所有者・終了結果を保持します。認証tokenは保存しません。
過去のowner不明ジョブを推測で移行・再送することはありません。
画像・3D・G8の公開schema、既存制作物、Blender登録、利用者のグローバル設定は変更しません。

旧版はこの終了通知記録を理解しないため、未送信結果の自動回収はできません。
旧版へ戻す前に処理を停止し、未送信・不一致のHost状態を確認してください。
DBバックアップへ戻す場合は、更新後の制作物と記録を先に退避してください。
v0.28.69のBlender反映journalに関する復帰上の注意も引き続き適用されます。

## 確認範囲と残件

配布データの除外修正を含め全1,789テストが通過し、ビューワービルドの生成差分はありません。
ソース版で、実Broker待機中の認証更新、診断用の元認証期限を越えた待機、通常取消による
ローカル・Host・資源要求の終了一致を確認しました。初期認証は診断用に180秒へ短縮しており、
通常の10分待機の成功とは区別します。
終了通知だけを意図的に失敗させた画像前提不足ジョブでは、専用ソース環境の再起動後、
同じ利用者の再認証で実Hostと元の失敗結果を照合できました。

追加の通常画像経路では、実Brokerの資源待ち後、約680秒で生成中を観測し、
約705秒でPNG・provenance・Host成功・終了通知済みを確認しました。
認証更新2回、GPU leaseのactivate1回・renew2回・release1回を実Host監査で照合しています。
待機時間は実LLM競合によるもので、初回認証TTLだけが診断用180秒です。
実行コードは本版の機能修正と同じソースですが、配布版の実績ではありません。
