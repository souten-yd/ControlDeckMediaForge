# v0.28.41 — 終わったら降ろしてから申告する

0.28.40 で入れたバッチが、走り終えた後も画像モデルを VRAM に抱えたままにしていました。
後始末は「続きが無ければ抱えない」ですが、その判定はバッチの宣言が立っている間に走る
ため素通りし、誰も降ろさないまま残ります。実機では 19.4GB を抱えたまま残り、直後の
音楽生成が GPU を 300 秒待って期限切れで失敗しました。

宣言した側が抜けるときに自分で降ろします。あわせて、単発の生成でも「完了を告げる前に
降ろす」順に変えました。抱えたまま成功を返すと、それを受け取った呼び出し側が次を
頼んだとき、GPU はまだ埋まっています。

## 検証

導入済み Host・実 GPU で、音声・効果音・音楽の生成を MCP 経路から確認しました。
単体テストは 1170 件が成功しています。

## 更新・ロールバック

0.28.40 からデータ変換はありません。0.28.40 への rollback は保存形式互換ですが、
バッチの後に画像モデルが VRAM へ残る問題が再発します。公開契約は変更していません。
