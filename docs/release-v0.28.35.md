# v0.28.35 — 履歴を残すBlender環境管理

停止済み・非既定の管理対象Blenderを、制作ファイルと履歴を残して削除できます。
履歴から参照される版は、既定オフの追加確認が必要です。再編集には同じ版の再導入が必要で、
設定の「この版を導入」から固定アーカイブを検証して導入できます。別の既定版や履歴の版指定は変えません。

稼働中・待機中のJob、GUI、作業コピーが参照する版や既定版は、追加確認でも削除できません。
受付と削除の排他、永続参照の集計、確認内容の再開時検査も含みます。
外部Blenderのファイル、利用者のグローバル設定、画像・制作物は削除しません。
Blenderとブラウザ操作環境は引き続き別の明示導入で、軽量配布には含めません。

検証済み範囲: sourceの実HTTP/Blenderで旧版削除・同版再導入・同scene GUI再起動、
日英1280/320の確認画面、日英320の実削除/再導入、旧版不在中のGLB表示とバックアップ保存。
全6 Asset関連ファイルとscene/revision保持、ZIP内の実bytesを照合しています。
source日英検証はlocale入力fixtureで、installed Hostの言語イベント受入とは別です。
統合3D Studioの全必須受入は引き続きPARTIALです。

公開後の追加確認: 公開artifactの再取得・Host信頼鍵検証と標準更新が完了し、installed
0.28.35はhealthyです。日英の設定確認・1280/320の初期表示で確認既定offと既定版の保護、
runtime状態不変を実Host画面で検証しました。本番runtimeの削除は行っていません。
試験環境でライブリサイズ直後のクリックが子画面に届かないケースは継続調査中です。

## 更新・ロールバック

ControlDeckの標準更新経路を使用してください。更新前にJob/GUI/環境処理の終端を確認し、
MediaForge DBとruntime registryのsnapshotを保管してください。
旧版coreへのrollbackは環境処理が終端してから行い、必要なBlenderの同版を保持・再導入してください。
旧coreにはこの確認付き削除・同版導入UIがありません。削除済み版を別の版で自動編集しません。
0.28.34より古いcoreへ戻す場合、外部登録抑止fieldを使用済みなら対応する旧registry snapshotの
復元も必要です。バイナリだけのrollbackで未知registry fieldが読めるとは扱わないでください。
