## Contract and boundaries

`media.scene.review` is an additive tool under the existing detached scene Job
manager, owner checks, revision/runtime pin, cancellation, retry and terminal
outbox. It accepts 2–4 observation image Assets including front and side, plus
the exact revision and intent. An explicit reference package ID must match the
revision dependency; omission automatically uses the attached package.

Observation provenance must identify the same scene, source hash, revision,
runtime, camera/specification and object IDs. Historical revisions are permitted.
The source hash and all cited inputs are checked again after inference. Reference
images come from the verified ZIP, including exact restored packages.

The current Host AI contract accepts at most four images. MediaForge prepares
one labelled observation sheet and up to two reference sheets, including a
distinct canonical image when present. Each sheet is at most 768 px per side.
Source hashes, submitted JPEG hashes/bytes, sheet IDs and pixel regions identify
what was actually submitted. Independent panel fitting is not metric calibration.
Host code/configuration is unchanged. The existing `vision.analyze` capability
owns provider selection and Broker admission; MediaForge holds no second GPU lease.

The model's output is bounded by a typed schema: at most three issues, explicit
image evidence, known object IDs where applicable, improvement suggestions and
limitations. Unknown evidence/objects and inconsistent verdicts fail closed.
Unsupported operation suggestions remain `needs_review`; no edit is executed.
An unavailable or failed vision call cannot become successful text-only review.

A successful Job stores `review.json` in an immutable ZIP Asset with input
lineage and a result projection. Deterministic revision checks remain separate
from the model's visual findings. `asset_approval=not_granted` and
`edits_executed=false` are fixed. Neither scene head nor ReferenceSet approval is
changed. Job success means review execution, not an accepted game asset.

Observation worker/results now preserve actual stable mesh IDs. Old observation
Assets without that field permit scene-level findings, not invented object IDs.
New `vision_review` / `publish_review` restart stages fail closed. CPU preparation
is drained before staging cleanup on cancellation; the awaited AI call is canceled.
Actual provider termination and Host resource release still require live acceptance.
