# G9 段の選択・端末写真・Web Blenderのモバイル操作

利用者の依頼は 4 つある。既定を trellis.cpp までにして Pixal3D を選べるようにする、
iPhone の写真を投入できるようにする、各機能の UI/UX を直す、Web Blender を携帯から
操作できるようにする。加えて「複数角度の画像で精度が上がるなら実装する」が条件付きで
付いている。以下は実装と、測って分かったことである。

## 1. 標準は trellis.cpp まで、Pixal3D は選んだときだけ

これまで `engine` は `auto` / `trellis_cpp` / `pixal3d` の三択で、どれか 1 つだけが走った。
`auto` は採用状況で勝手に決まるので、利用者から見ると「何が走るか分からない」。

`SceneFromImageRequest` に `refine_with_pixal3d`（既定 false）を足した。契約は追加のみで、
`engine` の意味は変えていない。既定の画面は `trellis_cpp` を選び、チェックを入れると
trellis.cpp の後ろに Pixal3D を足した 2 段で走る。`engine=pixal3d` を明示している場合は
すでに Pixal3D なので段は増えない。

段ごとに Host から lease を取り、段ごとに返す。またいで握らない。1 段目の成果物は
その時点でシーンとして publish し、2 段目は**同じシーンの次の版**として commit する。
どちらの Asset も残るので、並べて比べられる。これが「Pixal3D まで実行する」を選ぶ理由である。

2 段目が落ちても 1 段目の成果物は消さない。握り潰しではなく、結果に
`refine: {state, engine, reason}` を必ず載せ、画面も「trellis.cppの版は保存しました。
Pixal3Dの仕上げは完了しませんでした」と言う。採用されていない段を要求した場合は、
黙って 1 段へ落とさずに受付で断る。

admission の `generation_runtime_sha256` は 1 段目の receipt ではなく、順番を含めた
**段の並び全体**の digest にした。1 段目だけ見ていると、2 段目の採用が入れ替わっても
admission 後の検査を素通りする。

## 2. 複数角度の画像：実装しない（採用中の runtime が受けない）

条件が満たされなかったので実装していない。推測ではなく、採用している実体を読んだ結果である。

- `trellis-cli` の引数解析は `src/trellis_args.cpp:80` で `p.image = v` の単一代入である。
  `--image` を複数渡しても最後の 1 枚が勝つだけで、多視点条件付けの経路が無い。
  `--help` にも多視点入力の項目は無い（`tools/render_glb.py` の "multi-view render" は
  出来上がった GLB を複数方向から**描画**するツールで、入力側ではない）。
- Pixal3D の worker（`candidates/worker-surface32m-v1/worker_entry.py`）も `prepare` が
  `--input` を 1 枚受ける形で、複数視点を束ねる引数も manifest 項目も無い。

画面だけ複数枚を受けて内部で 1 枚に落とすのは「効くように見えて効かない」入力になる。
AGENTS.md の「止める判断」に従い、実装せず理由を記録する。再開条件は、上流が多視点
条件付けを持つ版を出し、その版を実測して採用し直したときである。

## 3. iPhone の写真

iPhone の既定は HEIC で、端末が JPEG へ直さずに添付してくることがある。

- 取り込みが復号できる形式を `pillow-heif` で足した。復号器が実際に Pillow へ載ったかを
  見てから宣言するので、入っていない環境では PNG / JPEG のままになる。保管する形式は
  今までどおり PNG へ正規化しており、Asset の `mime_type` 契約は増やしていない。
- 転送で名乗れる media type に `image/heic` ほかを足した。中身は必ず復号して確かめるので、
  ここは「端末がその名前で送ってくる」ものを通すためだけにある。
- EXIF の向きを取り込み時に当てるようにした。画面は復号時に向きを当てて寸法を測るので、
  当てないと測った寸法と預かった寸法が食い違う。横倒しのまま 3D の入力になると、
  前段の背景抜きが横倒しの物体を切り出す。
- 3D 生成の画面に「端末の写真を選ぶ」を置いた。`accept` は `image/*` と `.heic/.heif` で、
  iPhone の写真ライブラリとカメラがそのまま出る。端末が読めて core が受けない形式は、
  読めているうちに canvas で PNG へ直してから送る（既存の写真経路と同じ作法）。

## 4. Web Blender を携帯から

noVNC のジェスチャは 1 本指＝左ボタンで、**中ボタンのドラッグを作れない**。Blender の
視点操作は中ボタン（+Shift で平行移動）なので、指だけでは視点が動かせなかった。

- 「指の操作」を 選ぶ / 回す / ずらす / 寄る・引く から選ぶ。選ぶ以外のときだけ canvas へ
  届く前に touch を捕まえ、望んだボタンの mouse event を合成して渡す。「選ぶ」では
  何も横取りしないので、noVNC 本来のタップ・ドラッグ・2 本指スクロールがそのまま動く。
  「ずらす」は Shift + 中ドラッグなので、ドラッグの間だけこちらが Shift を握って離す。
  利用者が帯で Shift を押したままにしている分は、こちらで離さない。
- 修飾キー（Shift / Ctrl / Alt）は押したままにできる。押した瞬間に離す作りでは
  Shift+中ドラッグのような組み合わせが作れない。切断時は必ず離す。
- 画面キーボードは canvas では出ないので、隠し入力へ焦点を移して打たれた文字を keysym に
  して送る。Blender の G / R / S もこれで届く。
- 補助キーに numpad の 正面 / 右 / 上 と Home（全体）を足した。numpad を持たない端末では
  視点のリセットに手が出せなかった。

総称ボタン規則 `button:not(…):not(#shell-nav button)` が `:not()` の中に id を持つため、
class だけでも id 1 つでも勝てず、押す的が実描画で 39px になっていた。id を 2 つ書いて直した
（この罠は以前も踏んでいる）。
