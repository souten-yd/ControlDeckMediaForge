## Change

The existing image-to-3D form now derives its advanced engine selector from
`3d.image_to_3d.engines`. Automatic, trellis.cpp and Pixal3D use the resolutions
reported for the selected engine. Unavailable choices are disabled. Explicit
engine/resolution choices survive capability changes; an unavailable choice
blocks submission until the user selects an available choice. A legacy capability
without `engines` retains automatic selection. Unknown engines and unsupported
resolutions are excluded. Submission sends the existing `engine` argument.

CPU input preparation has its own localized status, separate from GPU admission,
generation, and scene validation/saving. Inputs survive cancellation, generation
failure, locale changes and a polling connection failure. The existing Refresh
action resumes polling. Scene, Asset, Jobs, transport and adoption authorities
remain those of the parent implementation.

The browser check exposed a cancellation race: starting a second job while the
first poll was sleeping left the second job without a monitor. Poll ownership is
now the job ID. An outstanding response, error or cleanup for the previous job
cannot replace the current job or clear its monitor. A late running response also
cannot undo a terminal cancellation.
