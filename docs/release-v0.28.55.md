# v0.28.55 — Blender導入中のディスク書き込みを非同期化

Blender/Web操作packのダウンロード中、ファイル書き込み・進捗保存・fsyncが
coreの応答を止め得る問題を修正します。これらをworker threadへ移し、
取消が重なっても開始済み書き込みを最後まで追跡します。
部分ファイルの不正な置換も拒否します。

## 検証と配布状態

PR #404で実装。進捗保存/fsyncがevent loop上で動く2件を再現して修正しました。
全1,384テストとビューワービルド、アニメーション表示5テストが成功しています。
実archiveの転送では、書き込み待ち中のHTTP応答、3回取消後の部分ファイル保持、
Range再開後の全377,929,956バイトのSHA-256一致を確認しました。
通信と遅延は試験用fixtureであり、実CDNやディスク満杯の受入ではありません。
署名公開・公開4ファイルの再取得照合・実Host署名検証を確認しました。
標準更新10.698秒でhealthyとなり、DB全テーブルとBlender登録を保持しています。
導入後は実CDNから同版4.5.9を再ダウンロードして通常修復し、58.081秒で成功。
47シーン・162版の情報と旧版関連64ファイルのハッシュを保持しました。
今回のブラウザ操作・導入済み環境での重複取消は未実施です。
最新の実測は[実装状況](implementation-status.md)へ記録します。

## 互換性と残る範囲

公開API/schema/tool、DB、Blender版・archive identityは変更しません。
既存画像・G8・ビューワーを維持します。実行中JobとGUIがない時に更新してください。
全setup処理の同期I/Oを解消した変更ではなく、metadata等の残件は別途対応します。
統合3D Studio全体、有機変形・IK・歩行等は引き続き開発中です。
